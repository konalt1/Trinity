# Dota 2 Workshop Core

## Сначала сверить проект

1. Прочитать `docs/AGENTS.md` и фактические точки подключения в коде.
2. Считать текущий код источником истины. Если он расходится с документацией, явно сообщить о расхождении.
3. Для незнакомого API свериться с актуальной документацией, не угадывать имя или семантику поля.

## VScript

Считать файл из поля `vscripts` приватным окружением конкретной entity. В нём доступен `thisEntity`; запись в настоящий глобальный scope делать явно через `_G`.

Подключать модули путём от корня `vscripts`, например `require("core.utils_server")`. Тело подключённого модуля выполняется в глобальном окружении и кешируется на VM. Поэтому держать внутренние объявления в `local` и возвращать наружу только публичное значение через `return`.

Порядок создания entity в одном кадре:

1. Выполнение файла скрипта.
2. `Precache`.
3. `Spawn`.
4. Событие `npc_spawn`, если entity является юнитом.
5. `Activate`.

`script_reload` перечитывает файлы и сбрасывает кеш `require`, но не повторяет `Precache`, `Spawn` и `Activate`. Логику, обязанную выполниться после reload, размещать в теле файла или вызывать явно.

`addon_init.lua` и `addon_game_mode_client.lua` не привязаны к entity и выполняются в глобальном scope. `addon_init.lua` выполняется раньше остальных файлов на сервере и клиенте; `addon_game_mode_client.lua` — только на клиенте.

Получать окружения entity через `GetPrivateScriptScope`, `GetPublicScriptScope` и варианты `GetOrCreate*ScriptScope`.

## KV в Trinity

### Подключение файлов

- Начинать с корневого KV и прослеживать все `#base` до определяющего файла.
- Способности подключаются цепочкой `Game/scripts/npc/npc_abilities_custom.txt` → `abilities/_index.txt` → тематический файл.
- При создании нового файла способности добавить его в `_index.txt` ровно один раз.
- Слоты героя менять в `Game/scripts/npc/npc_heroes_custom.txt`. Непереопределённый слот наследует ванильную способность.
- Сохранять ожидаемый корневой блок формата, например `"DOTAAbilities" { ... }`.

### Способности

- Для Lua-способности задавать `"BaseClass" "ability_lua"`.
- В `ScriptFile` указывать путь от `Game/scripts/vscripts/` без расширения `.lua`.
- Иконку задавать только в KV через `AbilityTextureName`; проверять файл в `Game/resource/flash3/images/spellicons/`.
- Игровые параметры хранить в `AbilityValues`; имя параметра должно точно совпадать с вызовом `GetSpecialValueFor` в Lua и ключом локализации `%name%`, если он выводится.
- Не добавлять новые блоки `precache` в KV Trinity. Прекешировать ресурсы в Lua через `Precache()` entry point или `PrecacheResource`. Существующие KV-блоки `precache` являются legacy, а не образцом для нового кода.
- Для масштабирования от Mind Power явно связать результирующий параметр и множитель в `MIND_POWER_RULES` файла `Game/scripts/vscripts/game_managers/custom_ability_tooltips.lua`. Не выводить связь автоматически только из наличия `mind_power_multiplier`.
- В серверной формуле использовать `GetHeroMindPower(caster)`, а не интеллект или stack count модификатора.

### Синтаксис и безопасное редактирование

- Сохранять кавычки, баланс фигурных скобок, регистр имён и табличную структуру соседнего файла.
- Не переименовывать KV-ключ без одновременной проверки Lua, локализации, слотов героя и UI-потребителей.
- При неоднозначности сначала найти все ссылки через `rg`, затем менять определение и потребителей одним согласованным патчем.
- Не считать успешный текстовый поиск проверкой синтаксиса: после изменения загрузить addon/ресурс и проверить консоль Workshop Tools.

## Локализация

Сохранять скомпилированные `Game/resource/addon_<lang>.txt` в UTF-8. UTF-16 загружается, но вызывает конвертацию и `PERF WARNING`.

Для способности проверять ключи `DOTA_Tooltip_ability_<name>`, `_Description`, `_Note`, `_Lore` и используемые `%special_value%`. В Trinity ориентироваться на структуру описаний способностей Лича.

## Чеклист новой способности

1. Добавить KV-определение и при необходимости `#base` в индекс.
2. Добавить/изменить слот героя.
3. Добавить Lua и подключение `require`, если оно нужно текущей архитектуре.
4. Прекешировать ресурсы в Lua.
5. Добавить иконку и `AbilityTextureName`.
6. Добавить RU-локализацию и EN при необходимости.
7. Сверить `AbilityValues`, `GetSpecialValueFor`, Mind Power rules и таланты.
8. Проверить загрузку в Workshop Tools и ошибки консоли.
